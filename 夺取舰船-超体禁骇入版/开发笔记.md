# 《夺取舰船》模组开发笔记

> 面向后续开发者（人或 AI）。本文记录本模组的完整架构、数值、驱动关系，
> 以及开发过程中遇到的所有问题、碰壁尝试与最终解决方案，供继续优化或新增机制时参考。
> 模组 id：`sw_capture`，游戏版本：Starsector 0.98a-RC8。

---

## 一、模组概览

本模组基于《Superweapons Arsenal 3.0（修改基础）》骨架改造而成，核心玩法为"夺取敌方舰船操控权"：

| 模块 | 类型 | id | 作用 |
| --- | --- | --- | --- |
| 骇入阵列 | 船体插件 | `sw_capture_array` | 锁定 1 艘敌方**无人舰**（余晖自动舰/无人机船）持续骇入，进度满后夺取操控权 |
| 跳帮舱 | 战机联队 | wing=`sw_boarding_wing`、战机=`sw_boarding_pod_wing` | 接触敌方**有人舰**累计跳帮计数，计数满后夺取操控权 |
| 跳帮驱动核心 | 船体插件（0 装配点） | `sw_capture_boarding_driver` | 驱动跳帮侧故障/过渡/修复等全部逻辑（仅与跳帮舱联动） |
| 一次性跳帮战机 | 机制（无实体定义） | — | 带累计跳帮计数的目标被击毁后，按其计数 × 返还系数释放一次性跳帮战机，继续跳帮"复仇" |

### 关键数值（默认，可在 LunaLib Mod Settings 调整）

- 接触需求次数：护卫 25 / 驱逐 38 / 巡洋 63 / 主力 100
- 跳帮接触距离：120；最大交战距离：4000；战机最高航速：300；战机更换时间：6
- 骇入范围：2600；骇入连锁范围：2000；骇入过渡 5 秒；跳帮过渡 10 秒
- 击沉返还系数：0.5（一次性战机释放数量 = 累计计数 × 0.5，向下取整）
- 故障判定间隔：跳帮 10 秒 / 骇入 5 秒；触发几率 = 0.2 + (进度 − 40%) × 1.0
  （40% 时 20%、50% 时 30%、70% 时 50%、100% 时 80%）
- 故障持续时间：骇入 40%~70% 区间 2.5 秒、70% 以上 4 秒；武器故障 8/16 秒；
  跳帮引擎/护盾 5 秒、武器 12 秒；重大故障 ×2
- 夺取后缓慢修复：每秒修复最大结构 0.5%，累计 40 次（40 × 0.5% = 20%）

### 夺取统一流程（跳帮侧与骇入侧共用）

```
进度满
  → 打「被夺取」标记（KEY_CAPTURED，跳帮舱/骇入阵列立即停止索敌与计数）
  → 进入过渡（瘫痪 + 无特效相位化；维持原阵营、不动舰长；时长跳帮 10s / 骇入 5s）
  → 过渡到时（tickCaptureTransitions）：切换阵营至我方 + 清舰长 + finishCapture
      （所属战机联队归我、停火重建 AI、修正原始归属）
  → 无条件打修复标记（每秒 +0.5% 结构，40 次后停止）
  → 战斗结束（敌方无存活部署 / 全部撤退 / isCombatOver）：
      归还原阵营 → 真正击沉（伤害来源 = 装有夺取插件的舰船，保证悬赏结算）
      → 清舰长 → 从敌方战斗管理器移除部署/预备 → 加入玩家战役舰队
```

## 二、模块驱动关系（重要）

这是本模组最容易出问题的部分，先讲清楚"谁在每帧驱动什么"：

```
引擎级每帧插件 CaptureCombatPlugin（EveryFrameCombatPlugin，引擎每帧调用，与模式无关）
   ├─ 每帧：HijackUtil.tickCaptureTransitions（过渡/修复）
   ├─ 每帧：HijackUtil.tickBattleEndSalvage（战斗结束收编检测，战斗中 0.5s 节流）
   ├─ 每帧：HijackUtil.checkGhostRelease（目标被击毁→释放一次性战机）
   ├─ 伤害监听：reportDamageApplied → tickBattleEndEarly（敌方最后一艘真船被击沉瞬间提前收编）
   └─ 战斗结束 3s 后：HijackUtil.postBattleRecover（战役层兜底收编）

船体插件 BoardingDriver（操控模式下引擎调用 advanceInCombat；策略模式下不被调用）
   ├─ 每帧：tickCaptureTransitions / tickCapturedWingAllegiance / tickBattleEndSalvage
   └─ 每帧+每10秒：全场被跳帮目标的故障倒计时与判定

船体插件 CaptureArray（骇入阵列，同上）
   ├─ 每帧：骇入目标选择/维持/进度施加、故障 tick 与判定
   └─ 每帧：tickCapturedWingAllegiance / tickBattleEndSalvage

战役层：
   CombatPluginRegistrar（Sector 常驻每帧脚本）→ 战斗引擎一创建即 ensureRegistered 引擎级插件
   PostBattleRecover（CampaignEventListener）→ reportBattleOccurred 注册引擎级插件 +
     reportBattleFinished 调 postBattleRecover
   WingSupplier（EconomyTickListener）→ 军事市场每日补货跳帮舱联队 + 跳帮驱动核心插件
```

**关键经验：Starsector 中船体插件的 `advanceInCombat` 只在"玩家处于操控模式（有玩家座舰）"时被引擎调用；策略模式（舰队控制面板）下不被调用。** 因此凡需要"任何模式下都持续推进"的逻辑（过渡计时、收编检测），必须放进引擎级插件 `EveryFrameCombatPlugin`，并由 Sector 级脚本/战役监听器保证其注册（不能只依赖船体插件首次调用触发）。

### 性能优化（第一正式版收尾时进行，2026-10）

1. **同帧去重节流**：`tickCaptureTransitions` / `tickCapturedWingAllegiance` 被 3 个驱动方（引擎级插件 + 2 个船体插件）每帧调用。新增按 `CombatEngineAPI` 实例的弱引用时间戳表（`TRANSITION_TICKED` / `WING_TICKED`），同帧只让第一个驱动方真正执行一次全战场遍历，其余直接返回。
2. **战斗收编扫描 0.5s 节流**：`tickBattleEndSalvage` 的"敌方无存活部署"检测无需每帧（击沉/撤退是渐变过程，0.5s 内必能检测到，结算面板生成前有充足缓冲）；`isCombatOver` 后不受节流、每帧扫描保证收编最优先。
3. **目标搜索降频**：
   - `CaptureArray.findBestHackTarget`（遍历全战场）每 0.5s 重搜一次，期间沿用旧目标/保持待机；
   - `GhostBoardingFighterAI.findNearestTarget` 每 0.25s 重搜一次，缓存目标失效时立即重搜（节流窗口内不自毁、等下个重搜点）。
4. **合并循环**：`BoardingDriver` 原来每帧对全场被跳帮目标跑两个遍历（故障 tick + 判定），合并为一个遍历，`allBoardingHits()` 快照拷贝从每帧 2 次降到 1 次。
5. **默认值修正**：`CaptureConfig.BOARDING_RANGE` 默认 180 → 120（与 modSettings.json / LunaSettings 一致，避免配置读取失败时行为偏差）。

## 三、踩坑清单（问题 → 尝试 → 结果 → 结论）

> 按主题分组。每条都是真实经历，标注最终采用的方案；未采用的方案也有记录，避免后人重复试错。

### 3.1 模组启动报错类

**1. CSV 文本中的裸 `%` 导致闪退**
- 现象：点开 LunaLib Mod Settings 某面板闪退，`Fatal: Conversion` / `JSONObject["fieldID"] not found`。
- 根因：LunaSettings.csv 的说明文本中含裸 `%`，LunaLib 解析时按格式化串处理炸裂。
- 解决：文本中 `%` 一律写成 `%%`；文件必须 UTF-8 **无 BOM**。
- 教训：所有被游戏/LunaLib 解析的 CSV 都要检查裸 `%` 与 BOM。

**2. CSV 文本中的引号/换行导致 `Mismatched quotes`**
- 现象：`Fatal: Mismatched quotes in the string; last quote: [持续骇入敌方无人舰船并夺取其操控权.graphics/...]`。
- 根因：hull_mods.csv 描述文本内使用英文引号或跨行拼接，CSV 解析错位。
- 解决：描述文本统一用中文引号"…"，单行内写完；desc 不含英文双引号。
- 教训：hull_mods.csv / wing_data.csv 的 desc 文本是"一行一字段"，内容里的引号与换行都会破坏结构。

**3. JSON 字段缺失/类型错误**
- `JSONObject["name"] not found`、`JSONObject["cost_frigate"] is not a number`、`JSONObject["id"] not found`、`JSONObject["fieldID"] not found`。
- 根因：wing_data.csv / ship_data.csv 等被改坏（列错位、字段被删、类型填错）；或 JSON/CSV 解析到空行/注释行。
- 教训：改动数据表时保持列数与表头一致；cost 类字段必须填数字；id 类字段不能留空；CSV 的 `#` 注释行放在表头上方而不是数据区。

**4. 船体插件描述文本导致"鼠标移上去闪退"**
- 现象：游戏正常运行，鼠标移到船体插件上闪退，`Fatal: Conversion ='以"` / `Fatal: Conversion='时'`。
- 根因：插件描述（desc）文本中含会被引擎当作转义/格式化处理的字符序列。
- 解决：仿照已正常显示的「骇入阵列」插件描述风格重写，避免特殊字符。
- 教训：船体插件 desc 文本要保守——不用英文引号、不裸用 `%`、不用可能被解释的转义序列。

**5. starfarer.api.jar 版本不匹配**
- 现象：`Fatal: WARNING:AoTD ... You must replace the 'starfarer.api.jar'`。
- 根因（背景）：某些模组（AoTD）要求特定版本的 starfarer.api.jar。
- 教训：模组开发基于 0.98a 原版核心 jar 编译即可，不要因为其他模组的要求去替换核心 api。

### 3.2 战机联队行为类

**6. wing 无母舰不被引擎驱动**
- 现象：用 `spawnShipOrWing` 直接生成 wing，战机不出来。
- 根因：原版战机联队依赖母舰存在/部署状态驱动重生与出击。
- 尝试：隐藏航母方案（gemini/condor/heron/legion 槽数折算）→ 成功但复杂；后弃用。
- 最终方案（方案 B）：`spawnShipOrWing("sw_boarding_wing")` 生成联队后，直接取 `wing.getWingMembers()` 拿到战机实体，多余战机当场 `engine.removeEntity`；战机由自写引擎级插件 `GhostBoardingFighterAI` **全权接管**（每帧 setFacing + 改写 `getVelocity()` 向量硬驱动直冲最近有人敌舰）。

**7. 战机 AI 绕圈/远射/远离目标**
- 现象：跳帮战机不靠近敌方，反而绕圈盘旋用武器攻击，或莫名远离母舰方向直飞。
- 根因：原版轰炸机/战机 AI 行为（保持距离、规避、攻击）与"贴脸跳帮"需求冲突。
- 尝试：NullAI（空 AI）接管 → 战机不动；相位化隐藏航母 → AI 直接撤退不释放；
- 最终：保留战机原版 AI（正常开盾/机动）用于**普通跳帮舱**；一次性战机用引擎级插件全权硬驱动覆盖。

**8. 母舰存活时 wing 无限重生，"alive=0 即移除"不可靠**
- 根因：原版 wing 由母舰持续补员。
- 教训：需要"一次性"语义的实体，不要依赖原版 wing 生命周期，用引擎级插件显式管理战机个体（生成→驱动→自毁→移除）。

**9. 一次性战机双重计数 bug（每架双计）**
- 现象：初始计数 12 的舰船，5 架一次性战机跳帮后，预期 17 实际 22（= 5 × 2）。
- 根因：`BoardingPod`（普通跳帮逻辑）没有跳过一次性战机，同一架战机被 `GhostBoardingFighterAI` 与 `BoardingPod` 各计一次；战机 customData 标记在 `spawnShipOrWing` 生成场景不可靠。
- 最终：静态弱引用身份集合 `HijackUtil.GHOST_FIGHTERS`（与 AI 插件同一实例判定必然一致）+ customData 标记双保险；`BoardingPod` 开头检查集合/标记跳过；AI 插件自毁/清理时同步 remove。

**10. 一次性跳帮导弹方案失败**
- 尝试：释放"同结构值的一次性导弹"代替战机 → 导弹被残骸碰撞吃掉/不可控，失败。
- 教训：Starsector 导弹实体行为不适合做"接触计数单位"，回归一次性战机方案。

**11. 跳帮舱不主动靠近（普通跳帮战机）**
- 现象：普通跳帮战机只远程用能量武器攻击。
- 根因：战机 AI 默认交战行为。
- 解决（用户方案）：联队类型设"轰炸机"、交战距离 4000、最大载员 15、必要载员 1、防御"全盾"；
  战机接触成功即**清空弹药与战备**，交给原版补给逻辑（战备/弹药归零自动召回母舰）形成"跳帮→返回补给→再出击"闭环；
  只有战备 > 0 的战机才可计数，机制上杜绝重复接触。

### 3.3 夺取/战后归属类（本模组最漫长的调试史）

**12. 战斗结算界面敌方"预备行动"残留原身**
- 现象：夺取舰船已加入玩家舰队，但敌方结算面板"预备行动"仍显示原身，形成"同一艘船两边都有"（舰船复制）。
- 尝试链：
  1. 夺取瞬间 `addFleetMember` 直接进玩家舰队 → 结算仍残留；
  2. `reportBattleFinished` 兜底 → 太晚，结算快照已生成；
  3. 伤害监听 `DamageListener.reportDamageApplied` 在"敌方最后一艘真船被击沉瞬间"提前执行收编 → 有效，但机制复杂；
  4. 复制+停机方案（复制同型号新船进玩家舰队、原体换回原阵营清零停机）→ 结算"预备行动"仍残留原身（复制成功但原身未归"停机或破坏"）；
  5. **回退到最终方案**：过渡结束切换我方 + 战斗结束（敌无部署/全撤退）归还原阵营 → 真正击沉（伤害来源=装有夺取插件的舰船）→ 清舰长 → 从敌方管理器移除部署/预备 → 加入玩家战役舰队。
- 教训：战斗结算快照在 `isCombatOver` 判定时定型，**晚于插件 advance**；只有引擎内部伤害事件回调能提前到快照之前；"击沉"必须用 `engine.applyDamage` 真正打掉（引擎记 destroyed，结算面板才归"停机或破坏"）。

**13. 策略模式（未切操控）下夺取逻辑失效**
- 现象：全程策略模式时夺取舰船跳过过渡、不清舰长、战后不进玩家舰队；切一次操控后一切正常。
- 根因：策略模式下船体插件 `advanceInCombat` 不被引擎调用 → 过渡驱动停摆。
- 尝试：引擎级插件 + 船体插件首次调用懒注册 → 仍依赖切过操控；战役级 `reportBattleOccurred` 注册 → 兜底；
- 最终：Sector 常驻脚本 `CombatPluginRegistrar` 每帧轮询 `Global.getCombatEngine()`，战斗引擎一创建立即 `ensureRegistered`（幂等，按引擎实例弱引用去重）。

**14. 战斗中新建战役成员无战备基线**
- 现象：战斗中把复制船 `addFleetMember` 进玩家战役舰队后，部署面板显示"🚫⭐️（战备为零）"，自动部署后带"⚡（强制撤退）"标志直接撤退；手动从 G 面板部署则正常。
- 根因：战斗中直接加入战役舰队的成员没有战役层战备数据/部署授权基线。
- 教训：不要指望战斗中直接写入战役舰队就能正常部署；部署语义必须走原版 `DeployedFleetMemberAPI` / 部署队列。本模组最终放弃"战斗中复制进玩家舰队"，改为战斗结束统一收编原体。

**15. 先击沉再复活 = 残骸化不复活**
- 尝试：夺取瞬间先把目标"真正击沉"再复活 → 目标残骸化，无法复活。
- 教训：引擎击沉流程不可逆，复活的任何做法都会遇到残骸状态残留。

**16. 相位化隐藏航母 AI 直接撤退且不自动释放战机**
- 尝试：相位化 + 完全不可见的隐藏航母自动释放战机 → AI 撤退、不释放。
- 解决：用代码强制释放一次跳帮战机，完成释放后 4 秒移除隐藏航母（引擎级插件自带生命周期，仿原版 ShardSpawner 母舰淡出移除）。
- 注：该方案（方案 A）最终被方案 B 完全替代（不再生成隐藏航母，直接生成战机）。

**17. 悬赏类任务结算**
- 要求：算作玩家击沉，悬赏正常结算。
- 解决：击沉伤害来源传装有「跳帮驱动核心」/「骇入阵列」的玩家舰船（`findCaptureSourceShip`），缺失时用玩家座舰/引擎。

### 3.4 计时与倍速

**18. 实时毫秒计时破坏战斗倍速**
- 尝试：用 `System.currentTimeMillis()` 做过渡计时 → 战斗 2 倍速时过渡仍按真实 10 秒走。
- 解决：一律用 `engine.getTotalElapsedTime(false)`（false = 不含暂停的实况战斗时钟，随倍速同步）。
- 教训：战斗内计时只认引擎时间；不要用系统时钟。

### 3.5 工具链经验（编译/部署）

- `javac` 在 Windows 下不展开 `*.java` 通配符，且 PowerShell 传参时单个含空格字符串不会自动拆分——用 `@(Get-ChildItem ... | ForEach-Object FullName)` 数组参数调用 `& javac ... @srcs`。
- 中英文双 jar 工作流：`src`（中文）→ 复制到 `src_en` → 运行 `en_floats.py`（把浮字等用户可见字符串替换为英文）→ 分别编译打包；中文 jar 部署到 `mods\夺取舰船` 与 `mods备份\夺取舰船`（两处 MD5 必须一致），英文 jar 放 `mods备份\ShipCapture_EN`。
- 验证用 `VerifyCapture.java`（关键类标签检查）在游戏 jre 下运行：`java -cp "capture_dev;Capture.jar;核心cp" VerifyCapture <jar路径>`。
- 数据文件（CSV/JSON/文本）全部 UTF-8 无 BOM；PowerShell 的 `Get-Content` 默认按 ANSI 解码，中文显示乱码是正常的，不代表文件损坏。

### 3.6 Mod Settings 可调"静态数据项"（写回数据文件）

**19. 战机联队的价值/装配点/联队数量/必要船员/更换时间、骇入阵列装配点数没有运行时 API**
- 尝试：直接 `MutableShipStatsAPI` 覆盖 → 编译验证后确认这些字段**只在数据文件加载时生效**（wing_data.csv / ship_data.csv / hull_mods.csv），stats 接口改不动它们。
- 解决：分两类处理——
  - **静态数据项**（市场价值/OP/联队数量/船员/更换时间/骇入阵列 OP）：LunaLib 设置变更回调 + `onGameLoad` 时调用 `CaptureConfig.applyStaticDataOverrides()`，把当前值**写回数据文件**（仅字段值变化才写，写回后读回校验），提示"重启游戏后生效"。
  - **战斗属性项**（航速/加减速度/结构/装甲/幅能容量/幅能耗散）：`MutableShipStatsAPI` 每帧 `modifyFlat(STAT_MOD_ID, 设置值 - 基础值)`（同 id 覆盖不叠加），保存后**即时生效**。
- CSV 写回细节：用行级区间替换（`csvFieldSpan` 定位目标字段的原始区间），只换字段值、不动整行，避免破坏含逗号/引号的 desc/tags 列；双引号字段按 CSV 规则转义（`"` → `""`）。
- 教训：数据文件里的"数值"不一定都能运行时改；先确认是否有对应 stats 接口，再决定走"运行时覆盖"还是"写回重启"。

**20. 0.98a API 方法名踩坑（编译期即可发现）**
- `ShipAPI` **没有** `getFaction()`；`ShipHullSpecAPI` **没有** `getMaxSpeed()/getAcceleration()/getDeceleration()`；`MutableShipStatsAPI` **有** `getEffectiveArmorBonus()`/`getArmorBonus()`，但**没有** `getEffectiveArmor()`。
- 正确取法：航速等基础值用 `stats.getMaxSpeed().getBaseValue()`（不含任何 modifier 的原始值）；结构/装甲/幅能用 `spec.getHitpoints()/getArmorRating()/getFluxCapacity()/getFluxDissipation()`。
- 战斗中无直接派系 API：超体类（Tesseract/欧米伽同派系）原版共用 `tesseract` 船体，用 `ship.getHullSpec().getHullId()` + 变体 id 前缀判定即可完整覆盖（`HijackUtil.isOmega`）。
- 教训：写新 API 调用前先 `javap -cp starfarer.api.jar <接口>` 查方法名，避免凭印象写方法名。

### 3.7 v2.1.0 新机制与精简滑块（2026-10）

**21. 跳帮目标开关（相位化/全盾）与骇入超体速度系数**
- 新增三个可调项：`boardPhasedAllowed`（默认否）、`boardOmniShieldAllowed`（默认是）、`hackOmegaSpeedMult`（0.05~1，默认 0.5）。

## 四、后续优化建议（留给后人）

- 一次性战机的生成单位是"联队（3 架）"，实际释放架数 ≥ 预期（向上取整到 3 的倍数）；若需精确架数可改为更细粒度生成。
- `tickBattleEndSalvage` 与 `tickBattleEndEarly` 功能有重叠（都是"敌方无部署→收编"），当前用 `EARLY_HANDLED`/`KEY_COPIED` 防重；未来可考虑合并。
- 故障系统目前是"引擎/武器/护盾三选一"，可扩展为组合故障或按舰船类型差异化。
- `CAPTURED_MEMBERS` 是强引用列表，正常流程会在 `postBattleRecover` 中逐艘移除；若战斗被异常中断（玩家强退），缓存可能残留到下次调用——当前已用"已在玩家舰队则移除"兜底，可继续观察。
- 所有 static 状态表均为弱引用（WeakHashMap / WeakSet），hulk 被引擎清理后自动消失，无需手动清。

- 待实测确认：关态是否切换成功；若 setSprite 对战机渲染无效（仍显示数据层贴图），日志会显示「匹配战机 X 架, 本次设置 Y 架」且 Y>0 但画面不变——届时需换数据层/渲染层方案。

### 踩坑记录（供后续开发者参考）
- **FleetSide 包路径**：`com.fs.starfarer.api.combat.FleetSide` 不存在，正确包为 `com.fs.starfarer.api.mission.FleetSide`（javac 报"找不到符号"即此）。其它包名务必以 `jar tf starfarer.api.jar` 核对。
- **编译输出乱码**：javac 报错按 GBK 输出，PowerShell 直接 `2>&1 | Out-String` 会吞输出（exit 1 无 stdout）；用 `$o = & javac ... 2>&1; $o | Select-Object -First N` 变量捕获可正常显示。
- **GL11 弧渲染**：必须把 `lwjgl.jar` / `lwjgl_util.jar` 加入编译 classpath（游戏 starsector-core 目录内），否则编译报找不到 org.lwjgl 符号；渲染 API（GL11.glBegin/glVertex2f/glLineWidth）与《Boarding Attack》一致，旧版 LWJGL2 兼容。
- **JSON 写入陷阱**：用字符串替换写多行 description 极易产生裸控制字符导致 JSON 解析失败；一律用 `json.dumps(ensure_ascii=False, indent=2)` 整体重建并二次 json.load 校验。
- **PowerShell here-string**：`@'...'@` 内容传给 python 时 `
` 会经 python 源码转义成真换行，凡需字面转义序列的文案一律在 python 内用显式 `
` 拼接，不要依赖 PowerShell 侧转义。
- **中英 jar 部署**：三处 jars/Capture.jar 中，英文版目录必须放英文编译产物（Capture_EN.jar 改名），曾误放中文 jar（哈希核对：A934DE…=ZH、553194…=EN）。

### 10.5 超体骇入失效（v3.0.0 发布后修复，2026-10）

- 现象：Mod Settings「骇入阵列：允许骇入超体类」开关关闭后超体**仍会被骇入**；调整「骇入超体类速度系数」**不生效**。
- 根因（两轮排查，第二版结论已修正）：
  - **0.98a 超体（omega 派系）原版变体带 automated 插件**（"无人舰"判定口径为 drone / automated 两类，
    超体落在 automated 一类）。第一轮排查曾误判"超体不带 automated"，结论错误，已在此纠正。
  - `validHackTarget` 原判定顺序是 `if (isUnmanned(t)) return true; return HACK_OMEGA_ALLOWED && isOmega(t);`——
    超体被 `isUnmanned` **先行放行**，开关开/关都拦不住（关闭失效）。
  - 速度系数在 CaptureArray 进度计算处：`(HACK_OMEGA_ALLOWED && isOmega(target)) ? HACK_OMEGA_SPEED_MULT : 1f`——
    开关关闭时恒为 1（系数自然"不生效"）。
  - LunaLib 读取链路经查**完全正常**：用户设置文件位于游戏 `saves/common/LunaSettings/sw_capture.json.data`
    （LazyLib `loadCommonJSON("LunaSettings/<modId>.json", ...)` 的 common 路径 = 游戏 saves\common），
    该文件存在且字段齐全（hackOmegaAllowed/hackOmegaSpeedMult 均在），`getBoolean("sw_capture", key)` 能读到用户值。
- 修复：`validHackTarget` 改为**超体优先判定、只由开关决定**：
  `if (isOmega(t)) return HACK_OMEGA_ALLOWED; return isUnmanned(t);`
  开关开 → 超体可骇入（速度按系数）；开关关 → 超体整体排除。普通无人舰判定不受影响。
- 教训：
  1. 不要凭旧版本/社区传闻假设船体插件构成；"无人舰"口径（drone/automated）与"超体类"是两套独立集合，
     需按语义分开关控制，且**先判超体**再判无人舰，否则 automated 会让超体混入普通无人舰。
  2. LunaLib 用户设置不在模组目录，而在游戏 `saves/common/LunaSettings/`（`.json.data` 后缀）；
     排查"开关无效"先确认该文件存在且字段值符合预期，不要先怀疑反射链路。
